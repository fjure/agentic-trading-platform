# Definition of Ready

- [x] HEAD, Bestand, Wiederverwendung und Sicherheitsgrenzen dokumentiert.
- [x] Guided und Advanced, ResearchIdea, Dialog, Testbarkeit und Quant-Vertical-Slice spezifiziert.
- [x] Proaktive Tagespipeline, identische Evidenz, Deduplikation, Budget und Wiederaufnahme spezifiziert.
- [x] Gateway, Capability-Vertrag, BYOK, Datenausleitung, Tool Policy, Approval und Berichte spezifiziert.
- [x] E2E A–G, Vertrag, Dashboard und Paketabhängigkeiten geplant.
- [x] NLP-01–12, exakte Vorschau und einmalige Sendefreigabe, lokaler Weg, fachliche Bestätigung und getrennte Quant-Zulassung spezifiziert.
- Strict Validation, Reviewbefunde und Remote-Abgleich siehe [Verifikation](planning-verification.md) und [Issue-Graph](issue-graph.md).

Apply erfordert einen neuen ausdrücklichen Auftrag und vollständig belegte Planungsabnahme. Offline-Implementierung kann bei einer späteren Freigabe HTTP-Doubles verwenden. Produktive BYOK-Eingabe, Schlüsselhaltung, Gateway-Egress und externe Datenklassen brauchen zusätzlich eine ausdrückliche Autorisierung. Provider, Profile, aktuelle Konditionen und Rechte werden dann separat belegt.
